# TutorPay — 데이터 모델 · 데이터 흐름 · 설계 결정

> 원칙 한 줄: **시스템이 원본, 시트·엑셀은 사본.** 저장 순간의 금액이 스냅샷으로 확정되어 이후 단가 개편·등급 변경에 소급되지 않고, 강의·정산·마스터 변경은 이력으로 남아 복원할 수 있다.

## 1. 데이터 모델 (ERD)

![ERD](../assets/erd.png)

테이블 15개를 다섯 묶음으로 나눈다.

| 묶음 | 테이블 | 역할 |
| --- | --- | --- |
| 단가 기준 | `grades` · `pay_types` · `rate_tables` · `rate_items` | 단가표 **버전**(`effective_from`)과 칸(등급 × 지급유형 × 역할 × 지역 그룹). 구간 단가는 `amount` / `amount_after` / `tier_limit` |
| 사람·기관 | `instructors` · `instructor_files` · `institutions` · `contents` · `content_aliases` | 마스터 데이터. 콘텐츠는 표준명 + 별칭, 처음 보는 표기는 `needs_review` 로 자동 등록 |
| 강의(핵심) | `lectures` | 강사 1명 = 1행. `unit_price` · `gross_amount` · `net_amount` · `tax_type` 을 **저장 시점 스냅샷**으로 보관. `instructor_id` NULL = 미배정 |
| 교구 | `equipment` · `equipment_rentals` | 가용 재고는 컬럼이 아니라 계산값(총보유 − 대여중 − 수리 − 폐기). `lecture_id` 로 강의와 연동 |
| 운영 | `users` · `audit_logs` · `settlement_locks` | 권한 3단계, 변경 이력(`before` / `after` jsonb), 월 정산 확정 잠금(`year` + `month` 복합키) |

**참조 무결성 규칙**

- `lectures → instructors / institutions` 는 `restrict` — 강의가 연결된 강사·기관은 삭제가 거부된다(급여 기록 보호).
- `rate_items → rate_tables / grades`, `content_aliases → contents`, `instructor_files → instructors` 는 `cascade` — 부모에 종속된 값.
- `equipment_rentals → lectures` 는 강의 삭제 시 연동 대여를 함께 정리하고, 대여 이력은 `audit_logs` 에서 개별 복원한다.
- `lectures.pay_type`, `lectures.content` 는 FK 가 아니라 **값으로 보관**한다. 스냅샷 원칙과 같은 이유로, 지급유형·콘텐츠 마스터를 나중에 고치거나 지워도 과거 강의 행이 바뀌지 않아야 하기 때문이다.

## 2. 데이터 흐름

### 강의 등록 → 급여 계산 → 정산 → 명세서

![급여 흐름](../assets/flow-payroll.png)

1. **입력 정리** — 콘텐츠 별칭을 표준명으로 치환하고, 차시 공란·단가 누락·미배정·등급 미등록은 경고로 목록에 노출한다.
2. **단가 결정** (`src/lib/calc.ts`) — `findRateTable`(적용 시작일 ≤ 강의일 중 최신 버전) → `pickRateItem`(등급 × 지급유형 × 역할, 강사 지역 그룹 칸 우선) → `grossOfItem`(경계 차시까지 기본 단가, 이후 구간 단가, 0.5차시 비례).
3. **세후** — `netOf` 가 세금 구분별(사업소득 3.3% / 기타소득 8.8% / 비과세)로 원 단위 절사. 교통비는 과세와 무관하게 더한다.
4. **스냅샷 저장** — 계산은 **서버에서만** 다시 수행한다(화면에서 넘어온 금액은 신뢰하지 않음). 결과를 강의 행에 확정하고 조회 시 재계산하지 않는다.
5. **정산** — 강사별 월 합계, 일괄 지급 처리, 월 확정 잠금. 잠긴 달은 등록·수정·삭제·지급 변경이 모두 서버에서 차단된다.
6. **산출물** — 강사별 명세서(인쇄/PDF), 월·기간·연간 엑셀, 대시보드·통합보고서.

## 3. 설계 결정 기록

| # | 영역 | 결정 | 이유 |
| --- | --- | --- | --- |
| 1 | 구조 | 구글 시트 7장을 DB 로 완전 이전, **시스템 = 원본** | 시트 수식의 소급 재계산·중복·결측 0원 처리 문제 제거 |
| 2 | 계산 | **스냅샷 원칙** — 저장 시 금액 확정, 이후 소급 없음 | 단가표·등급 수정이 이미 지급한 정산을 바꾸면 안 된다 |
| 3 | 계산 | 단가표 **버전제**(`effective_from`) — 개편은 새 버전 추가로만 | 과거 버전을 덮어쓰지 않아 어느 날짜든 같은 결과를 재현 |
| 4 | 계산 | 금액은 **서버에서만 계산** — 클라이언트 값은 표시용 | 화면 조작·낡은 탭으로 잘못된 금액이 저장되는 경로 차단 |
| 5 | 데이터 | 시트 결측은 임의 보정 없이 **경고로 노출** | 추정값이 급여에 섞이는 것보다 사람이 검수하는 편이 안전 |
| 6 | 데이터 | 콘텐츠 **표준명 + 별칭**, 모르는 표기는 검수 필요로 자동 등록 | 표기 변형(같은 콘텐츠의 서로 다른 이름) 때문에 집계가 갈라지는 문제 |
| 7 | 검증 | 이전 완료 조건 = 기존 시트 **558건 재계산 대조 불일치 0건** | 전환 신뢰 확보. 요율 개편 뒤에도 같은 대조를 다시 실행 |
| 8 | 권한 | **3단계**(admin / staff / viewer — 조회 범위 동일, 쓰기만 제한), 초기 관리자는 화면에서 끌 수 없음 | 실무자 입력은 허용하되 계정 관리는 분리, 전원 잠금 사고 방지 |
| 9 | 무결성 | 강사·기관 삭제는 강의 연결 시 **DB 에서 거부**(`restrict`) | 급여 기록 보호를 애플리케이션이 아니라 FK `restrict` 로 보장 |
| 10 | 무결성 | 교구 대여 용도는 **고정 5종** — 기존 변형 표기는 마이그레이션으로 정리 | 자유 입력이 만든 표기 변형을 원천 차단 |
| 11 | 세금 | **세금 구분을 강의 행마다 저장**(3.3 / 8.8 / 0%) | 같은 강사도 건별로 소득 구분이 달라질 수 있고, 이것도 스냅샷 대상 |
| 12 | 이력 | 강의·정산·마스터 변경을 `audit_logs` 에 `before` / `after` jsonb 로 기록, 삭제는 복원 가능 | 급여 데이터는 "누가 언제 무엇을" 이 항상 답해져야 한다 |
| 13 | 정산 | **월 확정 잠금** — 잠긴 달은 강의 등록·수정·삭제·지급 변경을 트랜잭션 안에서 거부(일괄 지급·복원은 액션 진입 시 검사) | 지급이 끝난 달의 사후 수정 방지 |
| 14 | 배포 | 마이그레이션은 **컨테이너 시작 시 자동 적용**, 배포 전 3중 검증 — 빈 DB 생성·재실행 멱등은 CI 가 매 푸시마다, 운영 DB 사본 적용은 수동 | 아래 4절 |
| 15 | 안정성 | 새 설치에서 개편 단가표가 비는 잠복 버그 수정 — 시드가 개편 버전까지 보장 | 빈 DB 검증에서 발견. 서버 이전 시 그대로 재현 가능해야 한다 |
| 16 | 인프라 | 앱은 **접속 문자열 외 인프라 의존 없음** — 같은 compose 가 EC2 단독(컨테이너 DB)과 RDS 분리 구성 모두에서 동작 | 서버를 옮겨도 코드 변경 없이 `.env` 와 DNS 만 바꾸면 되도록 |
| 17 | 보안 | IAM 은 **MFA 필수 · 액세스 키 미발급**, S3 업로드는 EC2 인스턴스 역할로, 청구 알림 설정 | 서버에 장기 자격 증명을 두지 않는다 |
| 18 | 네트워크 | Caddy 는 **443 만 사용**, TLS-ALPN 챌린지로 인증서 발급 | 80 포트를 쓸 수 없는 서버 조건에서도 자동 TLS 유지 |

## 4. 마이그레이션 3중 검증

요율 개편을 SQL 마이그레이션으로 관리하면서, 마이그레이션 하나가 실패해 앱 컨테이너가 재시작을 반복하고 프록시가 502 를 돌려준 일이 있었다. 이후 배포 전 검증을 절차로 고정했다.

1. **기존 DB 에 적용** — 운영 데이터 사본에 새 마이그레이션이 통과하는지
2. **재실행 무해(멱등)** — 같은 마이그레이션을 다시 돌려도 결과가 같은지
3. **빈 DB 에서 처음부터 전체 생성** — 0000 부터 끝까지 순서대로 통과하는지

세 경우 모두 `마이그레이션 완료` 로그를 확인한 뒤에만 배포한다. 15번 결정(시드 버그)은 3번 검증에서 발견됐다.

2026-10 부터 2번·3번은 GitHub Actions(`.github/workflows/ci.yml`)가 Postgres 서비스 컨테이너에서 매 푸시마다 수행하고, 이어서 가상 시드를 적재해 서버 액션 통합 테스트까지 돌린다. 1번(운영 데이터 사본 적용)은 운영 DB 덤프가 필요해 배포 전 수동으로 남긴다.

## 5. AWS 배포 구성 · 서버 이전 (2026-09)

```
Route 53 (A 레코드) ─▶ EC2 (Docker Compose)
                        ├ caddy   443, TLS-ALPN 자동 인증서 · HSTS
                        ├ app     Next.js, 시작 시 마이그레이션 자동 적용
                        └ db      PostgreSQL 16 (EBS 볼륨)  ── 또는 DATABASE_URL 을 RDS 엔드포인트로
                        cron: pg_dump | gzip ─▶ S3 (인스턴스 역할, 수명 주기 규칙)
```

2026년 9월 초 기존 서버에서 AWS 로 이전했다. **코드 변경 없이** 끝나도록 아래 절차로 진행했다.

1. **도메인 먼저** — 서비스 주소를 DNS 레코드로 고정해 두고(사용자는 IP 를 모른다), TTL 을 낮춰 둔다.
2. **새 서버 준비** — Docker 설치 → 저장소 배치 → `.env`(도메인·OAuth·DB 비밀번호) 작성.
3. **데이터 이전** — 기존 서버에서 `pg_dump` → 새 DB 에 복원. 빈 DB 기동 검증(4절의 3번)을 통과한 구성이므로 마이그레이션 상태가 그대로 이어진다.
4. **전환** — 새 서버에서 `docker compose up -d --build` 후 로그인·정산 화면 확인 → DNS A 레코드만 새 IP 로 교체. Caddy 가 새 서버에서 인증서를 다시 발급한다.
5. **되돌리기** — 문제가 있으면 A 레코드를 원래 IP 로 되돌린다. 전환 직전 덤프 이후 입력분만 다시 옮기면 된다.

## 6. 알려진 한계

각 항목은 **무엇 / 왜 그렇게 두었나 / 다음 조치** 순서. 괄호는 코드 위치.

| # | 무엇 | 왜 그렇게 두었나 | 다음 조치 |
| --- | --- | --- | --- |
| 1 | 사용자를 삭제해도 세션(JWT)은 만료(최대 14일, `src/auth.config.ts:11`)까지 남는다. 다만 `users` 행이 없는 세션은 2026-10 부터 거부한다(`src/lib/session.ts` `getCurrentUser`, `.env` 초기 관리자 목록만 첫 로그인 부트스트랩을 위해 예외). 이전에는 행이 없으면 `admin` 으로 잡혔다 | 차단은 삭제가 아니라 비활성화로 안내한다. 비활성화·삭제 모두 매 요청 DB 와 대조해 다음 요청부터 반영된다 | JWT 자체 폐기(세션 버전 컬럼)는 미구현 |
| 2 | 정산 잠금과 강의 쓰기가 동시에 들어오면 경합을 막지 못한다. 잠금 조회는 `FOR UPDATE` 없이 읽고(`lectures/actions.ts:73` `assertMonthUnlocked`), 잠금 등록은 진행 중인 쓰기를 기다리지 않는다(`lectures/actions.ts:635` `setMonthLock`) | 실무자 1~2명이 쓰는 전제 | `FOR UPDATE` 또는 advisory lock |
| 3 | 서버 액션 입력은 업무 규칙만 검사하고 구조(타입·필수 키)는 검증하지 않는다. 공통 유틸은 `num` / `str` 변환뿐(`src/lib/action-utils.ts:16`) | 호출자가 자체 화면뿐이라 뒤로 미뤘다 | zod 도입 |
| 4 | 트랜잭션 경계는 강의(`lectures/actions.ts`)·단가표(`rates/actions.ts`)·마스터 병합(`master/actions.ts`)·교구 일괄 대여(`equipment/actions.ts:195`)에만 있다. 강사·사용자·단건 교구 CRUD 는 변경과 감사로그가 별도 쿼리라 중간 실패 시 이력이 빠질 수 있다(`instructors/actions.ts`, `settings/actions.ts` 의 `logAudit(db, …)`) | 급여 금액에 닿는 경로부터 묶었다 | 나머지 액션도 트랜잭션으로 통일 |
| 5 | 동시 수정 충돌을 감지하지 않는다. `updateLecture` 는 조회한 `before` 와 저장 사이에 버전 비교가 없다(`lectures/actions.ts:376`) | 금액은 서버가 재계산하므로 낡은 탭이 저장해도 잘못된 금액은 들어가지 않는다 | `updated_at` 비교 또는 버전 컬럼 |
| 6 | 예외 메시지가 클라이언트에 그대로 전달되고 서버 로그는 남지 않는다(`src/lib/action-utils.ts:4` `safeAction`) | 예외 메시지를 사용자 안내문으로 쓰는 구조 | 내부 예외는 일반 문구로 바꾸고 서버에 기록 |
| 7 | `rate_items` 에 (단가표 · 등급 · 지급유형 · 역할 · 지역 그룹) 조합 UNIQUE 가 없다(`src/db/schema.ts:104` 인덱스만). 서버 액션도 조합 중복을 검사하지 않아(`rates/actions.ts:27` `createRateTable`) 화면 입력 구조로만 막는다 | 단가표는 버전 단위로 한 번에 입력된다 | UNIQUE 제약 마이그레이션 추가 |
| 8 | viewer 도 `/api/export` 로 전체 백업(`type=all`, 변경 이력 포함)을 내려받을 수 있다. 로그인만 확인한다(`src/app/api/export/route.ts:98`) | 권한 3단계는 조회 범위가 같고 쓰기만 제한하는 설계 | 내보내기를 staff 이상으로 제한 |
| 9 | 통합 테스트(`scripts/test/actions.test.ts`)는 시드를 적재한 DB 전용이고 정리 단계가 시작 시각 이후의 감사로그를 삭제한다. CI 는 매번 새 Postgres 컨테이너를 쓰지만 로컬에서는 compose DB 를 그대로 쓴다 | 별도 테스트 DB 없이 시작했다 | 로컬도 테스트용 DB 컨테이너 분리 |
